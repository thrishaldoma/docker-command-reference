QUESTION
========
## Objective

Containers on Docker's default network can only reach each other by IP address, which changes every time a container is recreated. On a **user-defined network**, Docker's built-in DNS lets containers find each other by name. In this lab you create such a network and show that name-based communication works.

## Tasks

### Task 1: Create a network

Create a user-defined bridge network named `app-net`.

### Task 2: Run a web server on it

Run a container in the background on `app-net`:

- name: `api`
- image: `nginx:1.30.6-alpine`

### Task 3: Run a client on it

Run a second container in the background on `app-net` that stays running:

- name: `client`
- image: `busybox:1.38.0`
- command: `sleep 3600`

### Task 4: Communicate by name

From inside `client`, request the page at `http://api` (using the container name, not an IP address) and save the result to `/home/user/name-test.txt` on this machine, for example:

```
docker exec client wget -qO- http://api > /home/user/name-test.txt
```

### Task 5: Record the network details

Create `/home/user/network-details.txt` with two lines:

```
api_ip=<IP address of the api container on app-net>
subnet=<subnet of app-net, in CIDR form such as 172.20.0.0/16>
```

## Notes

- Leave both containers running when you submit.
- Do not publish any ports: the containers talk over the private network.

## Expected outcome

`api` and `client` run on `app-net`, `client` reaches `api` by name, and the two files record the response and the network details.

ANSWER
======
```bash
docker network create app-net
docker run -d --name api --network app-net nginx:1.30.6-alpine
docker run -d --name client --network app-net busybox:1.38.0 sleep 3600
docker exec client wget -qO- http://api > /home/user/name-test.txt
docker network inspect app-net        # Subnet and the IPv4Address of api

ip=$(docker inspect -f '{{(index .NetworkSettings.Networks "app-net").IPAddress}}' api)
subnet=$(docker network inspect -f '{{(index .IPAM.Config 0).Subnet}}' app-net)
printf 'api_ip=%s\nsubnet=%s\n' "$ip" "$subnet" > /home/user/network-details.txt
```

APPROACH
========
1. Create the network with `docker network create app-net`.
2. Start `api` with `--network app-net`.
3. Start `client` with `--network app-net` and the command `sleep 3600`.
4. Run `docker exec client wget -qO- http://api` and check that it prints the Nginx page, then save it to the file.
5. Use `docker network inspect app-net` to find the subnet and api's IP address and write `network-details.txt`.

HINT
====
- `docker network create NAME` creates a bridge network.
- `docker run -d --name NAME --network NET IMAGE [COMMAND]` starts a container on that network.
- `docker network inspect app-net` shows the subnet and every container's address. `docker inspect -f '{{json .NetworkSettings.Networks}}' api` works too.

ORIGINAL SOLUTION SCRIPT (solve.sh)
===================================
#!/bin/bash
set -euo pipefail
docker network create app-net >/dev/null
docker run -d --name api --network app-net "$IMAGE_NGINX" >/dev/null
docker run -d --name client --network app-net "$IMAGE_BUSYBOX" sleep 3600 >/dev/null
for _ in $(seq 1 30); do docker exec client wget -qO- http://api > /home/user/name-test.txt 2>/dev/null && break; sleep 1; done
ip=$(docker inspect -f '{{(index .NetworkSettings.Networks "app-net").IPAddress}}' api)
subnet=$(docker network inspect -f '{{(index .IPAM.Config 0).Subnet}}' app-net)
printf 'api_ip=%s\nsubnet=%s\n' "$ip" "$subnet" > /home/user/network-details.txt
