QUESTION
========
## Objective

Three signals tell you most of what you need to know about a web service: how many requests it handles (**rate**), how many of them fail (**errors**) and how long they take (**latency**). You will build a Grafana dashboard with one panel for each, using the metrics Prometheus already collects from the `orders-api` service, and describe what each panel tells an engineer.

- Grafana: http://localhost:8802 (or **Open Grafana**), user `admin`, password `grafana@123!`
- Prometheus is already configured as Grafana's default data source and scrapes `orders-api` every 5 seconds.
- `orders-api` exposes `http_requests_total` (a counter with a `status` label) and `http_request_duration_seconds` (a histogram).

## Tasks

### Task 1: Create the dashboard

Create a dashboard titled `Orders API`.

### Task 2: Add the three panels

Add three time series panels that use the Prometheus data source, with exactly these titles and queries of this kind:

| Panel title | What the query must compute |
| --- | --- |
| `Request rate` | requests per second over all paths and statuses: `sum(rate(http_requests_total[1m]))` |
| `Error rate` | requests per second that returned a 5xx status: `sum(rate(http_requests_total{status=~"5.."}[1m]))` |
| `Latency p95` | the 95th percentile request duration: `histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket[5m])))` |

You may change the time window (for example `[2m]`) or show errors as a ratio of all requests, as long as each query computes what the table says.

### Task 3: Explain each panel

Give every panel a **description** (in the panel options) of at least six words that says what the panel indicates and when an engineer should worry, for example "Share of requests failing with server errors; a rise means users see failures".

### Task 4: Save

Save the dashboard.

## Notes

- In a new panel, switch the query editor to **Code** mode to type PromQL directly.
- The panels need a minute of data before lines appear.

## Expected outcome

A saved `Orders API` dashboard with Request rate, Error rate and Latency p95 panels whose queries return data from `orders-api`, each with a description.

ANSWER
======
Create the dashboard in the web interface as described, or with the HTTP API:

```bash
cat > /tmp/dashboard.json <<'END'
{
  "overwrite": true,
  "dashboard": {
    "title": "Orders API",
    "panels": [
      {"type": "timeseries", "title": "Request rate", "gridPos": {"x": 0, "y": 0, "w": 8, "h": 8},
       "description": "Requests per second handled by orders-api; sudden drops or spikes need a look.",
       "datasource": {"type": "prometheus", "uid": "prometheus"},
       "targets": [{"refId": "A", "expr": "sum(rate(http_requests_total[1m]))"}]},
      {"type": "timeseries", "title": "Error rate", "gridPos": {"x": 8, "y": 0, "w": 8, "h": 8},
       "description": "Requests per second failing with 5xx errors; any rise means users see failures.",
       "datasource": {"type": "prometheus", "uid": "prometheus"},
       "targets": [{"refId": "A", "expr": "sum(rate(http_requests_total{status=~\"5..\"}[1m]))"}]},
      {"type": "timeseries", "title": "Latency p95", "gridPos": {"x": 16, "y": 0, "w": 8, "h": 8},
       "description": "Time within which 95 percent of requests finish; higher means a slower service.",
       "datasource": {"type": "prometheus", "uid": "prometheus"},
       "targets": [{"refId": "A", "expr": "histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket[5m])))"}]}
    ]
  }
}
END
curl -s -u admin:'grafana@123!' -H 'Content-Type: application/json' \
  -X POST http://localhost:8802/api/dashboards/db -d @/tmp/dashboard.json
```

APPROACH
========
1. Log in to Grafana, choose **Dashboards**, **New**, **New dashboard**, **Add visualization**, and pick the Prometheus data source.
2. Enter the first query in Code mode, set the title and description, and go back to the dashboard.
3. Add the other two panels the same way.
4. Save the dashboard with the title `Orders API`.
5. Check that each panel shows data.

HINT
====
- `rate()` turns an ever-growing counter into a per-second rate; `sum()` adds up all label combinations.
- `status=~"5.."` matches every status that starts with 5.
- `histogram_quantile()` estimates a percentile from histogram buckets, grouped `by (le)`.
- The description field is in the panel editor's right-hand options, under the title.

ORIGINAL SOLUTION SCRIPT (solve.sh)
===================================
#!/bin/bash
set -euo pipefail
cat > /tmp/dashboard.json <<'END'
{
  "overwrite": true,
  "dashboard": {
    "title": "Orders API",
    "panels": [
      {"type": "timeseries", "title": "Request rate", "gridPos": {"x": 0, "y": 0, "w": 8, "h": 8},
       "description": "Requests per second handled by orders-api; sudden drops or spikes need a look.",
       "datasource": {"type": "prometheus", "uid": "prometheus"},
       "targets": [{"refId": "A", "expr": "sum(rate(http_requests_total[1m]))"}]},
      {"type": "timeseries", "title": "Error rate", "gridPos": {"x": 8, "y": 0, "w": 8, "h": 8},
       "description": "Requests per second failing with 5xx errors; any rise means users see failures.",
       "datasource": {"type": "prometheus", "uid": "prometheus"},
       "targets": [{"refId": "A", "expr": "sum(rate(http_requests_total{status=~\"5..\"}[1m]))"}]},
      {"type": "timeseries", "title": "Latency p95", "gridPos": {"x": 16, "y": 0, "w": 8, "h": 8},
       "description": "Time within which 95 percent of requests finish; higher means a slower service.",
       "datasource": {"type": "prometheus", "uid": "prometheus"},
       "targets": [{"refId": "A", "expr": "histogram_quantile(0.95, sum by (le) (rate(http_request_duration_seconds_bucket[5m])))"}]}
    ]
  }
}
END
curl -sf -u "$GRAFANA_USER:$GRAFANA_PASSWORD" -H 'Content-Type: application/json' -X POST "$GRAFANA_URL/api/dashboards/db" -d @/tmp/dashboard.json >/dev/null
rm -f /tmp/dashboard.json
sleep 20
