QUESTION
========
## Scenario

The `status-api` project in `/home/user/status-api` already has a working `Dockerfile` that copies the whole project folder into the image. Two problems were found in review:

1. The image contains files that must never ship: a local secrets file, log files and personal notes.
2. The app reads the environment variable `APP_ENV` to decide whether it runs in development or production, but the image does not set it, so it always reports `development`.

Fix both, rebuild, run the new image and explain what you added.

## Tasks

### Task 1: Add a .dockerignore

Create `/home/user/status-api/.dockerignore` so that these are **not** sent to the build and do not end up in the image:

- the file `secrets.env`
- every file ending in `.log`
- the folder `notes/`

The application files (`app.py` and `Dockerfile`) must still be included.

### Task 2: Set an environment variable in the image

Add an `ENV` instruction to the Dockerfile that sets `APP_ENV` to `production`.

### Task 3: Rebuild and run

Build the image as `status-api:2.0` and run it in the background:

- container name: `status-api`
- host port `8082` mapped to container port `5000`

`curl http://localhost:8082/` must then return `{"app": "status-api", "env": "production"}`.

### Task 4: Explain the additions

`/home/user/status-api/statements.txt` lists numbered statements. Create `/home/user/status-api/explain.txt` with two lines, naming the statement that correctly explains each addition:

```
dockerignore=<statement ID>
env=<statement ID>
```

## Notes

- Do not delete `secrets.env`, the logs or the notes from the project folder: excluding them from the image is the point.
- Leave the `status-api` container running when you submit.

## Expected outcome

`status-api:2.0` contains the app but none of the excluded files, reports `production`, runs on port 8082, and `explain.txt` names the right statements.

ANSWER
======
```bash
cd /home/user/status-api
printf 'secrets.env\n*.log\nnotes/\n' > .dockerignore
sed -i '/^FROM /a ENV APP_ENV=production' Dockerfile
cat Dockerfile
docker build -t status-api:2.0 .
docker run --rm status-api:2.0 ls -la /app      # no secrets.env, no logs, no notes
docker run -d --name status-api -p 8082:5000 status-api:2.0
curl http://localhost:8082/
```

The statements are shuffled per session. Pick the ones that say:

- `.dockerignore`: it excludes files from the build context, so they are never sent to the builder or copied into the image.
- `ENV`: it sets an environment variable that is stored in the image and available to every container started from it.

```bash
printf 'dockerignore=S2\nenv=S5\n' > explain.txt     # use your own IDs
```

APPROACH
========
1. Look at the project with `ls -la` and read the `Dockerfile`.
2. Write `.dockerignore` with the three patterns.
3. Add `ENV APP_ENV=production` to the Dockerfile, after `FROM`.
4. `docker build -t status-api:2.0 .`, then check the image contents with `docker run --rm status-api:2.0 ls -la /app`.
5. Run the container on 8082 and test it with `curl`.
6. Read `statements.txt` and write `explain.txt`.

HINT
====
- `.dockerignore` uses one pattern per line, for example `secrets.env`, `*.log` and `notes/`.
- `ENV NAME=value` sets an environment variable for the build steps after it and for every container started from the image.
- `docker run --rm IMAGE ls -la /app` shows what was copied into the image.

ORIGINAL SOLUTION SCRIPT (solve.sh)
===================================
#!/bin/bash
set -euo pipefail
cd /home/user/status-api
printf 'secrets.env\n*.log\nnotes/\n' > .dockerignore
sed -i '/^FROM /a ENV APP_ENV=production' Dockerfile
docker build -q -t status-api:2.0 . >/dev/null
docker run -d --name status-api -p 8082:5000 status-api:2.0 >/dev/null
for _ in $(seq 1 30); do curl -sf http://localhost:8082/ >/dev/null && break; sleep 1; done
d=$(grep 'build context' statements.txt | cut -d: -f1)
e=$(grep 'available to every container' statements.txt | cut -d: -f1)
printf 'dockerignore=%s\nenv=%s\n' "$d" "$e" > explain.txt
