QUESTION
========
## Objective

An **Ingress** routes HTTP requests from one entry point to different Services, based on the host name or the URL path. The cluster runs the Traefik ingress controller, which listens on port 80 of the node (`k3s`). You will publish two applications behind one Ingress, one per host name.

Two Deployments already run in the `web` namespace:

- `shop`, an Nginx server
- `blog`, an Apache httpd server

## Tasks

### Task 1: Create the Services

In the `web` namespace, create two ClusterIP Services:

- `shop-svc` on port `80`, selecting the `shop` Pods
- `blog-svc` on port `80`, selecting the `blog` Pods

### Task 2: Create the Ingress

Create an Ingress named `site-ingress` in the `web` namespace, with ingress class `traefik` and two rules:

- requests for host `shop.devops.local` go to `shop-svc` port 80 (path `/`, path type `Prefix`)
- requests for host `blog.devops.local` go to `blog-svc` port 80 (path `/`, path type `Prefix`)

### Task 3: Test the routing

The host names do not exist in DNS, so send the requests to the node and set the `Host` header yourself:

```
curl -H 'Host: shop.devops.local' http://k3s/
curl -H 'Host: blog.devops.local' http://k3s/
```

Save the two responses to `/home/user/ingress/shop.html` and `/home/user/ingress/blog.html`.

## Notes

- The `ingress` folder does not exist yet.
- Requests for any other host must not reach either application (Traefik answers 404).

## Expected outcome

`site-ingress` sends each host to its own Service, and the two saved pages come from Nginx and Apache respectively.

ANSWER
======
```bash
kubectl expose deployment shop --name=shop-svc --port=80 -n web
kubectl expose deployment blog --name=blog-svc --port=80 -n web
cat <<'END' | kubectl apply -f -
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: site-ingress
  namespace: web
spec:
  ingressClassName: traefik
  rules:
    - host: shop.devops.local
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: shop-svc
                port:
                  number: 80
    - host: blog.devops.local
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: blog-svc
                port:
                  number: 80
END
mkdir -p /home/user/ingress
curl -s -H 'Host: shop.devops.local' http://k3s/ > /home/user/ingress/shop.html
curl -s -H 'Host: blog.devops.local' http://k3s/ > /home/user/ingress/blog.html
```

APPROACH
========
1. Look at the deployments with `kubectl get deploy,pods -n web --show-labels`.
2. Create both Services.
3. Create the Ingress with `kubectl create ingress` or a YAML manifest with two `rules`, each with a `host` and an `http.paths` entry.
4. `kubectl describe ingress site-ingress -n web` shows the rules and backends.
5. Test with `curl -H 'Host: ...' http://k3s/` and save the responses.

HINT
====
- `kubectl expose deployment shop --name=shop-svc --port=80 -n web` creates a Service for a deployment.
- `kubectl create ingress site-ingress -n web --class=traefik --rule='shop.devops.local/*=shop-svc:80' --rule='blog.devops.local/*=blog-svc:80'` creates the whole Ingress in one command.
- Nginx answers "Welcome to nginx!", Apache answers "It works!".

ORIGINAL SOLUTION SCRIPT (solve.sh)
===================================
#!/bin/bash
set -euo pipefail
kubectl expose deployment shop --name=shop-svc --port=80 -n web
kubectl expose deployment blog --name=blog-svc --port=80 -n web
kubectl create ingress site-ingress -n web --class=traefik --rule='shop.devops.local/*=shop-svc:80' --rule='blog.devops.local/*=blog-svc:80'
kubectl rollout status deployment/shop -n web --timeout=300s
kubectl rollout status deployment/blog -n web --timeout=300s
mkdir -p /home/user/ingress
for _ in $(seq 1 30); do
  curl -sf -H 'Host: shop.devops.local' http://k3s/ > /home/user/ingress/shop.html && curl -sf -H 'Host: blog.devops.local' http://k3s/ > /home/user/ingress/blog.html && break
  sleep 2
done
