QUESTION
========
## Objective

Pods come and go, and each new Pod gets a new IP address. A **Service** gives a group of Pods one stable name and address, and keeps track of the current Pod IPs (its **endpoints**) through a label selector. You will put a ClusterIP Service in front of a Deployment and verify that it selects exactly the right Pods.

## Tasks

### Task 1: Deploy the backend

Create a Deployment named `backend` with `3` replicas and image `stefanprodan/podinfo:6.15.0`. Its Pods must have the label `app=backend`. The application listens on port `9898`.

A second Deployment named `backend-canary` already exists. Its Pods have the labels `app=backend-canary` and `track=canary`. It must **not** receive traffic from your Service.

### Task 2: Create the Service

Create a Service:

- name: `backend-svc`
- type: `ClusterIP`
- selector: `app=backend`
- port `80`, forwarding to target port `9898`

### Task 3: Verify the endpoints

Check the Service's endpoints. Save the output of `kubectl get endpointslices -l kubernetes.io/service-name=backend-svc -o wide` to `/home/user/endpoints.txt`.

### Task 4: Call the Service

From a temporary Pod inside the cluster, request `http://backend-svc/` and save the response body to `/home/user/backend-response.json`, for example:

```
kubectl run curl-test --image=busybox:1.38.0 --rm -i --restart=Never -- wget -qO- http://backend-svc/ > /home/user/backend-response.json
```

## Notes

- A ClusterIP address is reachable only from inside the cluster, which is why the request runs in a Pod.

## Expected outcome

`backend-svc` selects exactly the three `backend` Pods, and the saved response comes from one of them.

ANSWER
======
```bash
kubectl create deployment backend --image=stefanprodan/podinfo:6.15.0 --replicas=3 --port=9898
kubectl rollout status deployment/backend
kubectl expose deployment backend --name=backend-svc --port=80 --target-port=9898
kubectl get endpointslices -l kubernetes.io/service-name=backend-svc -o wide > /home/user/endpoints.txt
kubectl get pods -l app=backend -o wide
kubectl run curl-test --image=busybox:1.38.0 --rm -i --restart=Never -- wget -qO- http://backend-svc/ > /home/user/backend-response.json
cat /home/user/backend-response.json
```

APPROACH
========
1. Create the deployment and wait for it.
2. Create the Service with `kubectl expose` or a YAML manifest.
3. Compare `kubectl get endpointslices -l kubernetes.io/service-name=backend-svc -o wide` with `kubectl get pods -l app=backend -o wide`: the addresses must match, and no canary Pod may appear.
4. Run the temporary Pod and save its output.

HINT
====
- `kubectl create deployment backend --image=... --replicas=3` labels its Pods `app=backend`.
- `kubectl expose deployment backend --name=backend-svc --port=80 --target-port=9898` creates a matching ClusterIP Service.
- `kubectl get pods -l app=backend -o wide` shows the Pod IPs, which should be the endpoints.

ORIGINAL SOLUTION SCRIPT (solve.sh)
===================================
#!/bin/bash
set -euo pipefail
kubectl create deployment backend --image="$IMAGE_PODINFO" --replicas=3 --port=9898
kubectl rollout status deployment/backend --timeout=300s
kubectl expose deployment backend --name=backend-svc --port=80 --target-port=9898
sleep 3
kubectl get endpointslices -l kubernetes.io/service-name=backend-svc -o wide > /home/user/endpoints.txt
kubectl run curl-test --image="$IMAGE_BUSYBOX" --rm -i --restart=Never --quiet -- wget -qO- http://backend-svc/ > /home/user/backend-response.json
