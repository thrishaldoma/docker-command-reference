QUESTION
========
## Objective

Your team is planning to introduce a new feature in the application. To avoid disturbing the stability of the main branch, you have been asked to prepare a dedicated branch for development work. This way, the team can experiment, make changes, and test safely without affecting the production-ready codebase.

## Instructions

1. Navigate to the project directory located at `/home/user/app-metrics-docs`.
2. Review the existing branches in the repository to understand the current branch structure.
3. Create a new branch named `feature-update` to serve as the isolated workspace for the upcoming changes. (Do not switch to this branch yet.)
4. Confirm that the new branch has been successfully created and is listed alongside the existing branches.

## Notes

- Create the branch from the current `main` branch.
- Do not commit, merge or delete anything.

## Outcome

A new branch named `feature-update` will exist in the repository. The branch list will show it, but your active branch will still be `main`.

ANSWER
======
```bash
cd /home/user/app-metrics-docs
git branch
git branch feature-update
git branch          # * main is still the current branch
```

APPROACH
========
1. `cd /home/user/app-metrics-docs`
2. List the branches with `git branch` (add `-a` to see remote ones too).
3. Create the branch with `git branch feature-update`.
4. Run `git branch` again: `feature-update` is listed and `* main` is still marked as current.

HINT
====
- `git branch` lists local branches and marks the current one with `*`.
- `git branch <name>` creates a branch without switching to it. `git switch -c` and `git checkout -b` would switch.

ORIGINAL SOLUTION SCRIPT (solve.sh)
===================================
#!/bin/bash
set -euo pipefail
cd /home/user/app-metrics-docs
git branch
git branch feature-update
git branch
