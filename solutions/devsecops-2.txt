QUESTION
========
## Objective

Security checks belong in the pipeline, where they run on every change and stop problems before anything is built or shipped. You will add three kinds of scanning to a pipeline and make them a **required gate**: if any scan fails, the later stage does not run.

- **SAST** (static application security testing) with **Bandit**, which finds risky code patterns in Python
- **dependency scanning** with **Trivy**, which finds known vulnerabilities in the packages listed in `requirements.txt`
- **secret scanning** with **Gitleaks**, which finds credentials committed to the code

All three tools are installed on the runner.

- Gitea: http://localhost:8801, username `student`, password `student@123!`
- The repository `student/payments-api` is cloned to `/home/user/payments-api` (credentials saved). Its code has problems that all three scanners will find.

## Tasks

### Task 1: Write the pipeline

Create `.gitea/workflows/security.yml`, triggered on `push`, with two jobs on `ubuntu-latest`:

- `security`: checks out the code and runs, as separate steps:
  - `bandit -r app -lll` (fails on high-severity findings)
  - `trivy fs --scanners vuln --severity HIGH,CRITICAL --exit-code 1 .`
  - `gitleaks dir . --no-banner`
- `build`: checks out the code and runs `make build`. It must only run when `security` succeeds (`needs: security`).

### Task 2: See the gate block the build

Commit and push the workflow **without** fixing the code. The `security` job must fail and the `build` job must be skipped.

### Task 3: Fix the findings

Fix the code so all three scanners pass:

- in `app/app.py`, run `ping` without a shell: pass the command as a list, for example `subprocess.call(["ping", "-c", "1", host])`
- in `app/config.py`, remove the hard-coded secret and read it from the environment variable `AWS_SECRET_ACCESS_KEY` with `os.environ.get(...)`
- in `requirements.txt`, upgrade Django to the patched version `django==6.1.2`

Commit and push. The new run must pass both jobs.

## Notes

- The scanners run on the runner, not in your terminal. Their output in the run log names the file and line of every finding.
- Do not weaken the scans (no skips, ignore files or lower thresholds): fix the code.

## Expected outcome

The pipeline gates `build` on the three scans, one run shows the gate stopping the build, and the latest run passes after the fixes.

ANSWER
======
```bash
cd /home/user/payments-api
mkdir -p .gitea/workflows
cat > .gitea/workflows/security.yml <<'END'
name: Security
on: push

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - name: SAST with Bandit
        run: bandit -r app -lll
      - name: Dependency scan with Trivy
        run: trivy fs --scanners vuln --severity HIGH,CRITICAL --exit-code 1 .
      - name: Secret scan with Gitleaks
        run: gitleaks dir . --no-banner

  build:
    runs-on: ubuntu-latest
    needs: security
    steps:
      - uses: actions/checkout@v7
      - name: Build
        run: make build
END
git add .gitea && git commit -m "Add security gate" && git push      # security fails, build is skipped
```

Fix the findings:

```bash
sed -i 's/subprocess.call(f"ping -c 1 {host}", shell=True)/subprocess.call(["ping", "-c", "1", host])/' app/app.py
cat > app/config.py <<'END'
import os

settings = {"aws_secret": os.environ.get("AWS_SECRET_ACCESS_KEY", "")}
END
echo "django==6.1.2" > requirements.txt
git commit -am "Fix security findings" && git push                  # both jobs pass
```

APPROACH
========
1. Write the workflow with the two jobs and push it as it is.
2. In the Actions tab, open the failed run: `security` is red and `build` is skipped. Read each scanner's output.
3. Fix `app/app.py`, `app/config.py` and `requirements.txt`.
4. Push the fixes and wait for both jobs to succeed.

HINT
====
- `needs: security` under the `build` job makes it wait for, and depend on, the `security` job.
- Bandit's B602 finding means `shell=True` with a formatted string can run injected commands.
- Gitleaks reports the rule and the line, for example an AWS access key in `config.py`.
- Trivy lists each vulnerable package with the version that fixes it.

ORIGINAL SOLUTION SCRIPT (solve.sh)
===================================
#!/bin/bash
set -euo pipefail
cd /home/user/payments-api
wait_run() {
  local sha
  sha=$(git rev-parse HEAD)
  for _ in $(seq 1 120); do
    curl -sf -u "$GITEA_USER:$GITEA_PASSWORD" "$GITEA_URL/api/v1/repos/$GITEA_USER/payments-api/actions/runs?limit=20" \
      | python3 -c "import json,sys; d=json.load(sys.stdin); sys.exit(0 if any(r['head_sha']=='$sha' and r['status']=='completed' for r in d.get('workflow_runs') or []) else 1)" && return 0
    sleep 3
  done
  return 1
}
mkdir -p .gitea/workflows
cat > .gitea/workflows/security.yml <<'END'
name: Security
on: push

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - name: SAST with Bandit
        run: bandit -r app -lll
      - name: Dependency scan with Trivy
        run: trivy fs --scanners vuln --severity HIGH,CRITICAL --exit-code 1 .
      - name: Secret scan with Gitleaks
        run: gitleaks dir . --no-banner

  build:
    runs-on: ubuntu-latest
    needs: security
    steps:
      - uses: actions/checkout@v7
      - name: Build
        run: make build
END
git add .gitea && git commit -qm "Add security gate" && git push -q
wait_run
sed -i 's/subprocess.call(f"ping -c 1 {host}", shell=True)/subprocess.call(["ping", "-c", "1", host])/' app/app.py
printf 'import os\n\nsettings = {"aws_secret": os.environ.get("AWS_SECRET_ACCESS_KEY", "")}\n' > app/config.py
printf '%s\n' "$PIP_DJANGO" > requirements.txt
git commit -qam "Fix security findings" && git push -q
wait_run
