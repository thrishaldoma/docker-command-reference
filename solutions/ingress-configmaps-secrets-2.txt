QUESTION
========
## Objective

Configuration belongs outside the container image, so the same image can run in every environment. A **ConfigMap** holds non-secret settings, and Pods can receive them as environment variables. You will create a ConfigMap, inject it into a Deployment, and verify the values inside a running Pod.

## Tasks

### Task 1: Create the ConfigMap

Create a ConfigMap named `app-config` with these keys:

| Key | Value |
| --- | --- |
| `APP_COLOR` | `teal` |
| `APP_MODE` | `staging` |
| `MAX_UPLOAD_MB` | `25` |

### Task 2: Inject it into a Deployment

Create a Deployment named `config-demo` with image `busybox:1.38.0`, container name `app` and the command `sleep 3600`, that receives **all keys** of `app-config` as environment variables. Do not write the values themselves into the Deployment.

### Task 3: Verify inside the Pod

When the Pod is running, list its environment variables and save the three values to `/home/user/config-check.txt`, for example:

```
kubectl exec deploy/config-demo -- env | grep -E 'APP_|MAX_' | sort > /home/user/config-check.txt
```

## Notes

- Use `envFrom` with `configMapRef` (all keys) or one `valueFrom.configMapKeyRef` per key. Both take the values from the ConfigMap.

## Expected outcome

The running `config-demo` Pod has `APP_COLOR=teal`, `APP_MODE=staging` and `MAX_UPLOAD_MB=25` from the ConfigMap, and the saved file shows them.

ANSWER
======
```bash
kubectl create configmap app-config --from-literal=APP_COLOR=teal --from-literal=APP_MODE=staging --from-literal=MAX_UPLOAD_MB=25
cat <<'END' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: config-demo
spec:
  replicas: 1
  selector:
    matchLabels:
      app: config-demo
  template:
    metadata:
      labels:
        app: config-demo
    spec:
      containers:
        - name: app
          image: busybox:1.38.0
          command: ["sleep", "3600"]
          envFrom:
            - configMapRef:
                name: app-config
END
kubectl rollout status deployment/config-demo
kubectl exec deploy/config-demo -- env | grep -E 'APP_|MAX_' | sort > /home/user/config-check.txt
```

APPROACH
========
1. Create the ConfigMap and check it with `kubectl describe configmap app-config`.
2. Generate a Deployment manifest with `--dry-run=client -o yaml`, rename the container to `app`, and add `envFrom`.
3. Apply it, wait for the Pod, and check `kubectl exec deploy/config-demo -- env`.
4. Save the three variables to the file.

HINT
====
- `kubectl create configmap app-config --from-literal=KEY=value ...`
- `kubectl create deployment config-demo --image=... --dry-run=client -o yaml -- sleep 3600 > deploy.yaml` writes a manifest you can edit.
- Under the container, add:

```yaml
envFrom:
  - configMapRef:
      name: app-config
```

ORIGINAL SOLUTION SCRIPT (solve.sh)
===================================
#!/bin/bash
set -euo pipefail
kubectl create configmap app-config --from-literal=APP_COLOR=teal --from-literal=APP_MODE=staging --from-literal=MAX_UPLOAD_MB=25
cat <<END | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: config-demo
spec:
  replicas: 1
  selector:
    matchLabels:
      app: config-demo
  template:
    metadata:
      labels:
        app: config-demo
    spec:
      containers:
        - name: app
          image: $IMAGE_BUSYBOX
          command: ["sleep", "3600"]
          envFrom:
            - configMapRef:
                name: app-config
END
kubectl rollout status deployment/config-demo --timeout=300s
kubectl exec deploy/config-demo -- env | grep -E 'APP_|MAX_' | sort > /home/user/config-check.txt
